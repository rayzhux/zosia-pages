Root Cause

Category confusion

Four different jobs were blurred into one "search" concept. Cost optimization was the routing signal, not quality.

No routing taxonomy

Each file defined its own rules. They drifted independently with no single source of truth.

Doc-lookup was search-blind

Guessed URLs from training data instead of using Exa to find the canonical docs source.

No deep research trigger

"Deep research" had no definition. No instruction mapped it to deep_researcher_start with exa-research-pro.

Cost over quality

"web_fetch first (free)" trained the agent to avoid tools that produce better results.

Key Principles

Rules that emerged across 10 rounds

1
Substance beats verbs
Route based on the information need, not the user's word choice. "Research how Supabase handles realtime" is still a single-product docs question — it goes to doc-lookup despite the verb "research."
2
Exa finds pages. web_fetch reads them.
Discovery and extraction are different jobs. Never use web_fetch to "search" and never use Exa to "read a known URL."
3
Decompose compound prompts
If one sentence has multiple information needs ("read this URL AND tell me if X is supported"), split and route each sub-need independently.
4
Implicit comparison language upgrades to synthesis
"Deciding between," "worth switching from," "evaluating X vs Y" signal multi-product comparison even if the prompt leads with one product name.
5
Frontmatter must match body
Skill selection happens from descriptions first. If the frontmatter contradicts the body rules, routing breaks at the trigger layer.
6
Quality is the only routing signal
Cost never appears in the decision path. Route by which tool gives the best answer, not the cheapest call.
